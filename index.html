    🛡️ Privacy Architecture & Technical Disclosure

    Full technical transparency into how detection operates, data boundaries, and known limitations.

    1. Detection Engine Methodology

    This application uses a deterministic heuristic and pattern-matching engine (defined in js/analyzer.js). It evaluates structural indicators such as credential harvesting keywords, aggressive capitalization, high-pressure artificial deadlines, known deceptive domain patterns, and sensational news framing.

    Important: This is not a generative cloud AI model or a production security firewall. It does not replace enterprise antivirus, browser antiphishing protections, or professional editorial fact-checking.

    2. News & Claim Analysis Boundaries

    When news or viral claims are reviewed:

    • The system flags sensationalist wording, extreme emotional triggers, or claims that omit named sources.
    • The system never labels a claim as "False" unless authoritative proof is available. Because this local demo operates without an external fact-checking database API, claims are classified as Needs Verification.
    • Users are provided with actionable advice to verify claims with independent primary sources.

    3. Automatic Windows Notification Privacy

    • Local Processing Only: Notification text is processed strictly on your computer. No data is sent over the Internet.
    • Zero Persistent Storage by Default: Notification contents are held in volatile memory only for the duration of the session. If "Save Notification History" is checked, records are stored exclusively in your browser's private localStorage, which can be deleted with one click.
    • Content Unavailable Handling: If Windows privacy settings or lock screen security masks notification text, the detector reports that the text is withheld. It does not fabricate or guess hidden text.
    • App Filtering: You have full control over which applications are permitted to be inspected.

    4. Companion Architecture

    Browsers cannot read Windows toast notifications directly for security reasons. The provided Windows Companion (companion/WindowsNotificationCompanion.ps1) bridges the Windows 10/11 UserNotificationListener WinRT API to the local browser via loopback HTTP (127.0.0.1:8765).
